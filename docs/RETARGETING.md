# Retargeting

`FkRetarget` implements a restricted, deterministic, non-AI FK subset in the core and CLI. Same-skeleton CHR0 import remains independent and binds exact unique bone names.

`map-template <source.fpproj> <target.fpproj> <profile.json>` creates an **unapproved** profile with exact-name suggestions only. Review source/target fingerprints and BoneIds (stable source ID -> target ID), correct mappings manually, choose RootTranslation (`Reject` default, or explicit `CopyDelta`), then set Approved=true. No anatomy confidence is implied by name matching.

`retarget <source> <clip-index> <target> <approved-profile.json> <new-output>` adds the transferred clip to a cloned target project. It retains target mesh/binds and existing clips, preserves source inputs, saves the approved profile and sets branch metadata to target/fk. A new output path is required. Full branch-management UI is still pending.

Required subset: mapped ancestors/hierarchy match, local rest Euler axes match, rest scales are one. Rotation values transfer relative to source/target local rest angles without reducing full turns. Hermite tangents and key timing/locks remain unchanged. Translation is permitted only for mapped root under explicit CopyDelta (centimeters, no automatic proportion scaling). Other translation, scale channels, incompatible axes/hierarchy, incomplete mappings or stale fingerprints fail without dropping channels. This is animation transfer only, not mesh rebinding.

Desktop: choose **Map / Retarget**, load source and target FPPROJ files, choose the source clip, assign/unassign the target dropdowns, choose root policy and explicitly approve. Changing any assignment or policy revokes approval and clears the preview. Reset restores unapproved exact-name suggestions; Unassign all clears them. Load/Save profile preserves fingerprints and approval; stale fingerprints and unknown IDs fail transactionally. Preview transfer shows source and target skin side by side with a shared scrubber and separate orbit/zoom. Save new target project refuses existing files, including source/target files. The workbench's open project remains unchanged; load the saved target to edit it further.

Eight M1.D/D2 core tests plus an actual desktop smoke verify mapping transitions, renamed/proportioned rigs, input immutability, profile save/reopen and new-output enforcement. The alternate demo's rotated root intentionally fails the uncorrected matching-axis subset. Anatomical inference/confidence, viewport bone picking, axis/rest correction, twist distribution, contacts/IK, rebinding and facial/material mappings remain REQ-07 work. Supplied native Mario skeleton reports are reference inspection only; they are not compatible canonical projects or approved cross-game mappings.


## Semantic and rest-relative continuation

Source roles / Target roles opens native-identity-preserving annotations: aliases plus conservative hierarchy/rest-position inference, sides/chains/segments, toes/fingers/helpers/extras and explicit alternatives. Fields are manually correctable, lock after correction and can be excluded. Save/load role files checks skeleton fingerprints; corrections revoke mapping approval. Suggest by roles only maps unique role/side/segment matches and remains unapproved. Confidence labels describe heuristic evidence, not probabilities. Weights distinguish deform versus unweighted/helper, but richer weighted/length recognition and viewport picking remain pending.

Enable **Rest-axis / hierarchy transfer** for WorldRestDelta-v1. For row-vector matrices, desired target world rotation is targetRestRotation * inverse(sourceRestRotation) * sourceAnimatedRotation. Target local rotation then removes the animated target parent's rotation; target local offsets and inverse binds remain unchanged. Unmapped target helpers inherit their parents. Original source curves are evaluated at the requested fractional time, retained with winding/tangents inside a separate transfer layer, and never destructively rewritten. Tests cover independent small-rig poses, changed parents, rotated/asymmetric originals, identity and save/reopen. Strict FK keeps its old rejection rules.

Current rest-delta restrictions: scalar source curves only, unit rest scales, no animated scale, all animated source bones mapped, root-only explicit CopyDelta. Quaternion retargeting, scale compensation, nonroot translation/proportion/twist distribution and contact/IK are not implemented. The supplied Mario projects now contain real imported skin and animation; cross-rig mapping is not yet approved/tested.

**Bake for CHR0 / Bake for NUANMB** creates another clip, retaining the source. Integer samples are reconstructed as Euler Hermite or quaternion tracks and checked on a quarter-frame grid against world orientation/joints and roughly 64 representative vertices. Defaults are .5 degrees / .05 cm; failures reject rather than relax tolerances. Limit 2,000 frames / 100,000 bone-frame samples. Euler gimbal singularities and unsupported loop metadata reject. This is a measured subset, not continuous-error, winding-reconstruction or end-effector/contact proof. Genuine exports perform a second decoded-byte validation. Original same-rig CHR0↔NUANMB conversions pass; this does not establish Mario-to-Mario retargeting.
