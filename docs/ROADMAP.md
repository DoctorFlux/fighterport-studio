# Roadmap

Status describes acceptance criteria, not whole-game support. Local files are authoritative; GitHub issues are a small mirror.

- **M0.A Bootstrap — tested:** fresh root, .NET 10.0.402, core/CLI/WPF/worker/test projects, local scripts, ignored tool caches.
- **M0.B Private source repository — verified and pushed:** exact owner recorded in config/repository.json; first checkpoint 2192e76 pushed after staged review and privacy verification.
- **M0.C Discovery/CI — partial:** bounded registry doctor; full versioned manual overrides, standard-location discovery and signed release packaging pending. Manual-only workflow prepared; no CI run.
- **M1.A Original assets — synthetic tested:** two humanoid rigs including 30 finger joints, different names/proportions/root orientation; third tail-chain variant. Idle/walk/punch/crouch/jump/full-spin/hold/scale/tangent clips. Procedural geometry and checker texture; no commercial inputs.
- **M1.B Workbench — tested subset:** New/Load/Demo, depth-buffered CPU skinned WPF viewport, orbit/pan/zoom, skeleton selection/markers, play/pause/scrub, scalar key edit, undo/redo, atomic save/reopen. MVVM separation beyond core EditSession, complete asset tree, bone-line overlay, transform gizmos and advanced editing remain.
- **M1.C Canonical representation — partial:** v1 hierarchy, bind matrices, normals/UV0/weights, Hermite/Euler curves, provenance/hash-retained originals. Tangents, colors, morphs, curve time domains, advanced scale semantics, native metadata, durable target branches and migration fixtures still need expansion.
- **M1.D Restricted FK mapping — synthetic tested in core/CLI:** fingerprinted manual mapping profiles, explicit approval/coverage, rotation deltas for matching rest axes/hierarchy, explicit root translation policy, immutable target mesh/binds and source inputs. Five tests cover renamed rigs, stale/unapproved/incomplete maps, axes/hierarchy rejection, full turns and root policy. Desktop mapping controls and general anatomical inference are still pending.
- **M2.A Genuine MDL0 v11 fixture/read — synthetic tested:** BrawlLib-generated original geometry through normal native importer, parent-first canonical hierarchy plus native indices/exact inverse binds, UV0/normals/1–4 weights. No retail/native-tool check.
- **M2.B CHR0 v4 native edit loop — synthetic tested:** separate animation import/export, exact name binding, nonconstant motion, integer Hermite keys, fractional evaluation, loop/scale/tangent/full-turn tests, source unchanged, save/reopen + decode compare. Unsupported discontinuities/step export rejected. Other native versions and scale compensation pending.
- **M2.C Harden/independently validate — pending:** fuller malformed-offset fuzzing, process quotas/progress, native BrawlCrate UI checks (shared backend), native mathematical pose comparisons (basic independent mesh/UV/normal/weight/rotated-bind comparisons now pass), source relink/packaging UI, external known fixtures when supplied.
- **M3.A Character mapping — planned:** deterministic anatomical roles by aliases/topology/positions/lengths/weights; confidence/alternatives; source/target selection, manual locks/chains/axis/rest corrections/reusable exact fighter profiles; proper rest alignment/proportion/root/twist handling; rebinding distinct from motion; IK/contact corrections later.
- **M3.B Optimization — planned:** retained reference; target-aware error bounds at keys/intermediate/contacts/end effectors/skinned vertices; discontinuities/winding/loops/locked keys; real encoded size, decode error, budgets supplied per target; no silent tolerance change; no automatic geometry reduction.
- **M3.C Ancillary synchronized channels — planned:** native generated VIS0/SRT0/PAT0/CLR0/SHP0 fixtures, actual editable playback, explicit channel loss/substitution policies; SCN0/others separate. PAC/PCS/BRRES dependency/preservation and packaging.
- **M3.D Materials — planned:** non-destructive Melee/Brawl/Ultimate/Rivals style presets; regions, source textures/normals/palettes/ramps/masks/colors/transparency, packing/baking and correct color spaces. Verify official Rivals ORMS and base-color settings before implementation.
- **M4.A First cross-game route — planned:** verified interchange both directions; Brawl-to-Rivals 2 source import package and reverse editable-source animation export; official installed Modkit version detection/editor automation; validate/cook only with tool present. Source export distinct from cooked extraction.
- **M4.B Native tool/DCC round trips — planned:** BrawlCrate, Melee tools, SSBH Editor, Rivals Modkit; Blender/Maya/Max equal host bridges with IDs, hashes, skeleton fingerprint, units/axes/time ranges, stale/conflict checks, control-rig bake. FBX/glTF subsets/DAE/SMD/ANIM only on verified paths.
- **M5.A Melee — planned:** HSDLib/HSDRaw/MMW DAT joints, skins, binds, materials/textures, AnimJoint/FigaTree and actual native ancillary structures; slot/build/revision profiles and native write/decode checks.
- **M5.B Ultimate — planned:** ssbh libraries/editor; NUMDLB/NUMSHB/NUSKTB/NUMATB/NUANMB/NUTEXB, transform/visibility/material channels, explicit physics/morph limitations; read/write/preservation separate.
- **M5.C Dragon Ball SOURCE ONLY — planned:** Sparking ZERO, FighterZ, Xenoverse 1/2 separately; FModel/CUE4Parse/UEViewer and LibXenoverse families; versions/master skeleton/dependencies/compression/facial losses; no destination exporter.
- **M5.D Sources/installations — planned:** bounded lazy indexing, logical bundles, revision evidence, missing dependencies, read-only extracted paths then independently verified GameCube/Wii/nod, Switch, Wii U, 3DS and N64 readers. No keys/ROM downloads/DRM bypass. Archive traversal/decompression quotas and corruption diagnostics.
- **M5.E Remaining fighters — planned:** separate Wii U and 3DS adapters, verify NUD/NUT/VBN/OMO/BCH; distinct Smash 64 pipeline; future independent game adapters; costumes and remaining channels.

Gameplay/moveset/hitbox conversion is excluded; preserve opaque resources and report remaining game integration. Asset export never equals a playable fighter. Initial UI and synthetic tests do not complete M1/M2 in full.
